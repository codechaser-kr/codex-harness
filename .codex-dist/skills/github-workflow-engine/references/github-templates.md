# GitHub Template Contract

Workflow Engine은 이슈와 PR 본문에 사람이 확인할 작업 내용, 판단 근거, 완료 기준만 남긴다.

이 파일은 GitHub Workflow Engine이 사용하는 템플릿 계약 문서다. 실제 이슈와 PR 본문 형식의 단일 원천은 타겟 레포의 `.github/ISSUE_TEMPLATE/*.md`와 `.github/pull_request_template.md`다.

Workflow Engine은 이 파일을 title prefix, label, 필수 섹션, 연결 규칙을 판정하는 런타임 계약으로 사용한다.

## 이슈 템플릿

### 기능제안

제목 prefix: `[기능제안] `

라벨: `기능제안`

필수 섹션:

- `무엇을 제안하나요?`
- `왜 필요한가요?`
- `현재 상태는 어떤가요?`
- `판단 결과`
- `판단 근거`
- `완료 기준은 무엇인가요?`

`판단 결과`는 생성 시 미체크로 두고, 진행 방향 확정 뒤 `진행하지 않음`, `정책 검토 필요`, `기능 변경 필요` 중 하나만 최종 체크한다.

`판단 근거`는 생성 시 비워 둔다. 진행 방향이 확정되면 Workflow Engine이 사용자가 확정한 방향의 근거를 기록한다.

`완료 기준은 무엇인가요?`는 생성 시 비워 둔다. 진행 방향이 확정되면 Workflow Engine이 확정 방향에 맞는 체크항목 하나를 미체크로 추가하고, 후속 작업이 해당 항목을 체크하면서 기능제안 이슈를 종료한다.

방향별 완료 기준 항목:

- `진행하지 않음 결정 반영`
- `정책검토 흐름으로 전환`
- `기능변경 흐름으로 전환`

### 정책검토

제목 prefix: `[정책검토] `

라벨: `정책검토`

필수 섹션:

- `무엇을 결정해야 하나요?`
- `왜 지금 필요한가요?`
- `선택지는 무엇인가요?`
- `검토 결과`
- `후속 작업은 무엇인가요?`
- `연관 이슈`

기본 후속 작업:

- `정책 검토 결과 확정`
- `결정된 정책을 관련 설계 문서에 반영`
- `기능 변경 이슈로 전환`

정책검토의 `검토 결과`에는 설계 문서 반영 후 기능변경 전환 범위를 기록한다.

### 기능변경

제목 prefix: `[기능변경] `

라벨: `기능변경`

필수 섹션:

- `어떤 기능을 변경하려 하나요?`
- `왜 필요한가요?`
- `작업 범위는 어디까지인가요?`
- `어떤 효과가 기대되나요?`
- `완료 기준은 무엇인가요?`
- `추가 정보`
- `연관 이슈`

작업 범위는 `포함`과 `제외`를 나누어 쓴다. 변경 계획이 확정되면 작업 범위에 모든 브랜치/PR 단위 ID와 작업 내용을 기록하고, 완료 기준에는 각 브랜치/PR 단위 ID와 작업 내용이 일대일로 대응하는 체크항목을 둔다.

### 기능결함

제목 prefix: `[기능결함] `

라벨: `기능결함`

필수 섹션:

- `어떤 문제가 있나요?`
- `문제 유형은 무엇인가요?`
- `재현 과정 또는 확인 위치가 어떻게 되나요?`
- `올바른 동작은 어떻게 되나요?`
- `원인과 해결 방향은 무엇인가요?`
- `완료 기준은 무엇인가요?`
- `추가 정보`

문제 유형은 `코드 버그`, `문서와 구현 불일치`, `정책 문서 간 불일치`, `반영 누락`, `기타` 중 해당 항목을 체크한다.

### 기능제안 후속 이슈 작성

기능제안에서 정책검토 또는 기능변경으로 전환하여 새 이슈 초안을 작성할 때는 원본 기능제안 이슈 본문의 `무엇을 제안하나요?`, `왜 필요한가요?`, `현재 상태는 어떤가요?`, `판단 결과`, `판단 근거`를 초안 작성 근거로 사용한다.

새 정책검토 또는 기능변경 이슈 본문의 `연관 이슈`에는 원본 기능제안 이슈 번호를 기록한다.

## PR 템플릿

필수 섹션:

- `왜 변경하려 하시나요?`
- `어떻게 변경하려고 하나요? (optional)`
- `해당 변경으로 영향받거나 검토해야 할 사항은 무엇인가요? (optional)`
- `머지하기 전에 반드시 확인되어야 할 사항이 있다면 작성해 주세요. (optional)`
- `연관 이슈 (optional)`

`연관 이슈 (optional)`에는 Workflow Engine이 연결 이슈를 파싱할 수 있도록 `Refs #번호`를 사용한다.

`머지하기 전에 반드시 확인되어야 할 사항이 있다면 작성해 주세요. (optional)`에는 PR merge 전에 끝나야 하는 선행 조건만 적는다. 다른 PR merge, 정책 결정, 배포 창구, 마이그레이션, 설정 변경, 권한 부여 같은 외부 조건이 없으면 `N/A`를 유지한다. 검증 결과와 일반 진행 체크리스트는 해당 목적의 본문 섹션에 기록한다.

Workflow Engine 관리 PR의 연결 키워드는 `Refs #번호`다.

## 이슈 유형별 라벨

Workflow Engine이 이슈 유형 판단과 이슈 생성에 사용하는 프로젝트 라벨 이름은 다음 네 가지로 제한한다.

- `기능제안`
- `정책검토`
- `기능변경`
- `기능결함`

이슈 유형 판단은 제목 prefix보다 라벨을 우선한다. 제목 prefix와 라벨이 충돌하면 사용자 결정으로 넘기고, 사용자가 선택한 유형을 반영한다.

Issue Creation Skill은 이슈 유형별 라벨 집합 안에서 이슈 유형에 맞는 라벨 하나를 선택한다. 이슈 유형별 라벨 집합에 없는 라벨을 임의로 추가하지 않는다.
