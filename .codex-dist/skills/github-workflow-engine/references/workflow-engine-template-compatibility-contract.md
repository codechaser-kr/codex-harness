# Workflow Engine 템플릿 정합성 계약

이 계약은 Workflow Engine이 타겟 저장소에 필요한 GitHub 템플릿을 최초 적용하거나 기존 템플릿의 운영 상태를 감사(audit)할 때 사용한다. 적용 시점은 `target-runtime-bootstrap-contract.md`가 정하며, Harness 설치나 생성 과정에서는 이 계약을 실행하지 않는다.

## 런타임 원천 확인

템플릿을 적용하거나 감사하기 전에 같은 스킬의 `github-templates.md`를 읽는다.

title prefix, label, 필수 섹션, 이슈 유형별 선택지, 후속 작업, PR 연결 규칙은 `github-templates.md`에서 가져온다. 이 계약은 해당 기준을 타겟 저장소의 템플릿에 적용하고 정합성을 판정하는 절차만 정의한다.

## 기대 파일과 요구 범위

타겟 저장소에는 다음 파일을 기본 매핑으로 둔다.

- `.github/ISSUE_TEMPLATE/proposal_template.md`
- `.github/ISSUE_TEMPLATE/decision_template.md`
- `.github/ISSUE_TEMPLATE/feature_template.md`
- `.github/ISSUE_TEMPLATE/fix_template.md`
- `.github/pull_request_template.md`

타겟 저장소가 다른 파일명을 사용하더라도 런타임 원천의 title prefix, label, 필수 섹션, PR 연결 규칙을 만족하는 파일을 매핑 대상으로 정하고 근거를 기록한다. 최초 초기화에서는 현재 작업이 요구하는 이슈 유형 또는 PR 템플릿만 대상으로 삼고 다른 템플릿을 미리 만들지 않는다.

## 적용과 갱신

1. 런타임 원천에서 현재 필요한 이슈 유형 또는 PR 규칙을 읽는다.
2. 타겟 저장소의 기존 `.github` 템플릿과 파일 매핑을 확인한다.
3. 매핑 대상이 없으면 런타임 원천의 구조와 데이터를 사용해 필요한 템플릿을 작성한다.
4. 기존 템플릿은 필수 기준과 타겟 전용 확장을 구분해 감사한다.
5. 필수 기준을 유지하는 설명, 추가 섹션과 도메인 확장을 허용된 타겟 확장으로 판정하고 보존한다.
6. 필수 기준이 누락되거나 충돌하면 자동으로 덮어쓰지 않고 차이, 영향 범위, 수정 후보를 제시한다.
7. 사용자가 갱신 범위를 확정한 경우에만 필요한 부분을 갱신한다.
8. 현재 이슈 유형의 라벨 존재 여부를 확인하고, 누락 시 Workflow Engine이 권한과 명령 경로를 검증해 생성한다.
9. 변경 내용, 보존한 확장과 매핑 근거를 감사 가능한 결과로 남긴다.

## 감사 항목

이슈 템플릿은 다음 항목을 런타임 원천과 대조한다.

- YAML frontmatter의 `title`과 title prefix
- YAML frontmatter의 `labels`와 유형별 라벨
- 타겟 GitHub 저장소의 해당 이슈 유형 라벨 존재 여부
- 런타임 원천에 정의된 필수 섹션
- 기능제안의 `판단 결과` 선택지
- 정책검토의 기본 후속 작업 체크리스트
- 기능변경의 `포함`·`제외` 작업 범위
- 기능결함의 문제 유형 선택지

PR 템플릿은 다음 항목을 런타임 원천과 대조한다.

- 런타임 원천에 정의된 필수 섹션
- `머지하기 전에 반드시 확인되어야 할 사항이 있다면 작성해 주세요. (optional)`의 merge 선행 조건 용도
- `연관 이슈 (optional)` 섹션
- `Refs #번호` 안내 또는 기본값
- Workflow Engine 관리 PR의 `Refs #번호` 연결 키워드 기본값

## 판정과 사용자 결정

- `정합`: 런타임 원천의 필수 기준과 연결 규칙을 모두 충족한다.
- `허용된 확장`: 런타임 원천의 필수 기준을 유지하면서 타겟 도메인용 섹션이나 설명을 추가한다.
- `불일치`: 런타임 원천의 필수 기준이 누락되거나 충돌한다.

`정합`과 `허용된 확장`은 파일을 변경하지 않는다. `불일치`는 차이, 영향 범위, 수정 후보를 사용자에게 제시하고 갱신 범위가 확정될 때까지 원래 작업을 중단한다.
