# Logging Contract

이 문서는 MD-only 하네스에서 세션 기록을 어디에 남기고 어떻게 유지할지 정의한다.

로그도 실행 결과를 설명하는 문서여야 한다. TSV나 임시 상태 파일보다 사람이 읽고 다음 역할이 바로 이어받을 수 있는 Markdown 기록을 우선한다.

## 핵심 전제

- 세션 기록의 진실원천은 Markdown 문서다.
- 기록의 목적은 통계 수집보다 다음 역할과 다음 세션이 바로 이어받게 하는 데 있다.
- 로그는 선택 사항이 아니라 실행 완료 조건의 일부다.
- 세션 기록은 누적 저널과 최신 요약으로 나눈다.
- `latest-session-summary.md`는 다음 실행 판단에 직접 필요한 최신 상태만 담는다.
- 세션 환경 메모, 승인 이력, 일회성 권한 문제는 `session-log.md`에 누적한다.

## 필수 로그 문서

- `.harness/docs/logging-policy.md`
- `.harness/logs/session-log.md`
- `.harness/logs/latest-session-summary.md`

상황에 따라 반복 흐름과 개선 후보는 `.harness/docs/*` 운영 문서나 `latest-session-summary.md`의 다음 조치에 함께 남긴다.
자기진화형 하네스에서는 새로 확인한 저장소 사실과 반복될 수 있는 판단도 다음 실행의 입력이다. 이 항목은 별도 스크립트나 상태 저장소가 아니라 Markdown 로그에 남긴다.

## logging-policy.md 계약

`logging-policy.md`는 프로젝트 로컬 하네스가 어떤 로그를 왜 남기는지 설명하는 운영 문서다. 예전 스크립트 사용법을 복사하는 문서가 아니며, 자동 append 도구나 TSV 이벤트 파일을 필수 조건으로 적지 않는다.

### 생성 책임

`logging-policy.md` 초안은 `Phase 0` 감사 뒤 시작 문서를 준비할 때 시작 진입 역할(`run-harness`)이 만든다. 이 문서는 초기에는 최소 로그 정책을 고정하는 문서이며, `Phase 5`에서 흐름 조율 역할이 `session-log.md`, `latest-session-summary.md`와 맞춰 갱신한다. `Phase 6`에서는 운영 감사 역할이 세 문서가 같은 로그 계약을 말하는지 검증한다.

역할별 책임은 아래처럼 나눈다.

- `Phase 0` / 시작 진입 역할: `logging-policy.md` 초안을 만들고 필수 로그 문서와 기록 목적을 고정한다.
- `Phase 5` / 흐름 조율 역할: 실제 handoff, 재진입 흐름, 세션 종료 기준에 맞춰 로그 정책과 로그 예시를 정렬한다.
- `Phase 6` / 운영 감사 역할: `logging-policy.md`, `session-log.md`, `latest-session-summary.md`가 같은 필드와 완료 기준을 말하는지 검증한다.

최소 포함 항목:

- 로그 목적
- 필수 로그 문서
- 세션 시작 기록 항목
- 역할 완료 기록 항목
- 최신 요약 기록 항목
- 학습 후보와 승격 대상 기록 기준
- 보류/실패 기록 기준
- 완료 전 확인 기준

권장 원칙:

- 사람이 직접 읽고 이어받을 수 있는 Markdown 기록을 우선한다.
- 명령이나 스크립트는 보조 확인으로만 둔다.
- `session-log.md`와 `latest-session-summary.md`의 필드 이름이 이 문서와 어긋나면 로그 정책을 먼저 고친다.
- 생성기 환류 후보는 단일 타겟 관찰과 반복 결함을 구분해서 적는다.

## session-log.md 계약

`session-log.md`는 세션 단위 저널이다. 같은 세션 안에 여러 항목을 누적할 수 있다.

각 세션 기록은 최소한 다음을 포함한다.

- 시각
- 세션 ID
- 상태
- 시작 요청
- 진입점
- 계획 역할
- 호출 역할
- 실행 결과 상태
- 입력 요약
- 출력 요약
- 변경 파일
- 다음 권장 역할
- 남은 위험
- 메모

세션 중 발생했지만 다음 세션의 첫 판단에 매번 필요하지 않은 정보는 `session-log.md`에 남긴다.

예:

- 환경 메모: `.codex` 경로가 세션 중 읽기 전용으로 시작해 외부 승인으로 디렉터리를 생성함.
- 승인 이력: 쓰기 권한, 샌드박스 예외, 네트워크 접근 승인 여부
- 일회성 맥락: 특정 실행 환경에서만 발생한 임시 제약이나 우회

## latest-session-summary.md 계약

`latest-session-summary.md`는 가장 최근에 종료된 세션의 상태 중 다음 실행 판단에 직접 필요한 정보만 한 번에 읽을 수 있게 정리한 문서다. 다음 시작 역할, 재진입 Phase, 다시 읽을 입력, 최근 변경, 운영상 위험을 빠르게 판단하는 데 집중한다.

최소 포함 항목:

- 세션 ID
- 시작 시각
- 종료 시각
- 기록 수
- 계획 역할
- 호출 역할
- 역할 결과 상태
- 최근 입력 요약
- 최근 출력 요약
- 최근 변경 파일
- 마지막 권장 역할
- 다음 재진입 phase
- 남은 위험
- 다음 시작 전 우선 확인 입력 파일
- 최근 출력 파일
- 세션 종료 메모

자기진화 루프가 필요한 세션에서는 아래 항목도 포함한다. 관찰이 없으면 `없음`으로 짧게 남긴다.

- 학습 후보
- 반복 신호
- 승격 대상
- 생성기 환류 후보

권장 형식:

```markdown
- 학습 후보: `<facts or 없음>`
- 반복 신호: `<pattern or 없음>`
- 승격 대상: `<Phase and target or 없음>`
- 생성기 환류 후보: `<yes/no and reason>`
```

`남은 위험`에는 다음 작업의 역할 선택, 재진입 Phase, 검증 기준, 실행 순서에 직접 영향을 주는 위험만 둔다. 세션 환경 메모, 승인 이력, 일회성 샌드박스/권한 문제는 `남은 위험`으로 승격하지 않고 `session-log.md`의 메모로 남긴다.

## 결과 상태 규약

역할 결과 상태는 아래 값 중 하나를 쓴다.

- `planned`
- `in_progress`
- `completed`
- `timed_out`
- `failed`

시작 이벤트처럼 아직 실행 결과가 없는 항목은 상태를 비워 둘 수 있다. 실제 역할 수행을 기록할 때는 가능한 한 결과 상태를 남긴다.

## 기록 규칙

- 역할 실행이나 문서 변경이 있으면 같은 세션 기록에도 남긴다.
- 비동기 역할은 최종 응답 전에 `completed` 또는 `timed_out`으로 정리한다.
- `timed_out`과 `failed`는 숨기지 말고 남은 위험과 후속 조치로 연결한다.
- 새 저장소 사실, 역할 오판, 검증 공백, 보존 문서 충돌을 확인했다면 학습 후보와 승격 대상을 남긴다.
- 생성기 환류 후보는 여러 타겟 프로젝트에서 반복될 가능성이 있을 때만 적고, 단일 타겟의 일회성 관찰은 로컬 보강으로 남긴다.
- 세션 환경 메모, 승인 이력, 일회성 권한 문제는 `session-log.md`에 기록하고, 다음 실행 판단에 직접 영향을 줄 때만 `latest-session-summary.md`의 운영상 위험으로 요약한다.
- 통계 자동화보다 재진입 가독성을 우선한다.

## 최종 응답 전 게이트

하네스 작업을 마치기 전에는 현재 세션 ID가 `session-log.md`와 `latest-session-summary.md`에 모두 남아 있는지 확인한다.

`logging-policy.md`가 없거나, 세 문서 중 하나가 다른 로그 계약을 말하면 완료가 아니라 로그 보강 필요 상태로 본다. 이때 최종 응답에는 완료 대신 남은 로그 보강 항목과 다음 조치를 남긴다.

## 완료 조건

하네스 작업이 끝났다고 말하려면 최소한 다음 조건을 만족해야 한다.

- `session-log.md`에 현재 세션의 주요 진행과 종료가 남아 있다.
- `latest-session-summary.md`가 마지막 종료 세션 기준으로 갱신돼 있다.
- `logging-policy.md`가 Markdown 로그 정책과 최신 요약 필드를 설명한다.
- 다음 역할 또는 다음 재진입 Phase가 명시돼 있다.
- 다음 시작 전에 다시 읽을 입력과 최근 출력이 남아 있다.
- `latest-session-summary.md`의 남은 위험이 다음 실행 판단에 직접 필요한 내용으로 제한돼 있다.
- 환경 메모와 승인 이력은 `session-log.md`에만 남아 있거나, 다음 실행 판단에 직접 영향을 주는 경우에만 최신 요약에 운영상 위험으로 짧게 요약돼 있다.

## 다른 레퍼런스와의 연결

- `reentry-rules.md`: 요약 문서에 어떤 재진입 정보를 남겨야 하는지 정의한다.
- `evolution-contract.md`: 학습 후보, 반복 신호, 승격 대상, 생성기 환류 후보의 의미를 정의한다.
- `verification-checklist.md`: 로그 문서가 최소 기준을 충족하는지 검토할 때 쓴다.
- `target-evaluation-playbook.md`: 로그를 읽고 운영 가능/재작성 필요/재구성 필요를 판정할 때 쓴다.
