# Quality Evaluation Guide (사용자 판단을 위한 하네스 비교 관찰 기준)

이 문서는 타겟 프로젝트에 생성된 실행 하네스의 `with-skill`과 `without-skill` 결과를 사용자가 직접 비교할 수 있도록 관찰 자료를 준비하는 기준을 정의한다.

하네스와 역할 에이전트는 두 결과의 우열, 품질 향상 또는 운영 적합성을 최종 판정하지 않는다. 생성기 저장소에서는 비교 자료 준비 계약이 갖춰졌는지만 확인하고, 실제 타겟 결과의 의미와 선택은 사용자가 판단한다.

---

## 핵심 전제

- 구조 검증 결과는 비교 자료의 일부일 뿐 하네스 품질의 충분한 근거가 아니다.
- 같은 요청의 원본 결과와 관찰 가능한 차이를 나란히 보존한다.
- 에이전트는 `좋다`, `나쁘다`, `개선됐다`, `더 적절하다` 같은 우열 결론을 만들지 않는다.
- `현재 유지 / 부분 수정 / 구조 재설계` 선택과 변경 범위는 사용자가 확정한다.

---

## 1. 비교 대상

가능하면 같은 요청과 같은 저장소 기준선에서 다음 두 결과를 준비한다.

- `without-skill`: 하네스 없이 일반적인 실행 경로를 사용한 원본 결과
- `with-skill`: 현재 하네스 구조, 입력 메모, 역할 정의와 역할 스킬을 사용한 원본 결과

두 실행의 요청, 기준선, 사용한 경로 또는 실행하지 못한 이유를 함께 기록한다. 조건이 다르면 직접 비교 가능한 자료로 가장하지 않고 차이를 제한 사항으로 남긴다.

---

## 2. 최소 관찰 항목

다음 항목은 값을 해석하거나 점수화하지 않고 실제 차이만 기록한다.

### 1) 시작 역할

- 각 결과가 선택하거나 제시한 시작 역할 수와 이름
- 시작 역할 선택 근거의 유무

### 2) 사용자 질문

- 각 결과가 제시한 질문 수와 질문 내용
- 질문이 요구한 추가 입력

### 3) 다음 역할과 재진입

- 다음 역할 또는 하네스 Phase가 명시됐는지
- 보류·실패 시 재개 조건이 남았는지

### 4) 저장소 근거

- 실제로 인용한 파일, 설정, 로그와 사용자 입력
- 근거 없이 추정한 항목과 확인하지 못한 항목

### 5) 검증 자료

- 실행한 명령과 결과
- 구조·계약 검증의 통과·실패
- 미실행 항목과 이유

---

## 3. 선택 관찰 항목

프로젝트에 따라 다음 사실도 함께 제공할 수 있다.

- 역할과 handoff 수
- 생성하거나 변경한 파일
- 중단과 재개 조건
- 상위 `AGENTS.md`와의 충돌
- 반복 실행에서 달라진 출력

이 항목도 우열 판단이나 가중치 없이 원본 근거와 차이만 남긴다.

---

## 4. 비교 결과 표현

비교 자료는 아래 순서로 남긴다.

1. 요청과 공통 기준선
2. `without-skill` 원본 결과 요약
3. `with-skill` 원본 결과 요약
4. 관찰 가능한 차이
5. 직접 비교할 수 없는 조건과 불확실성
6. 구조·계약 검증 결과
7. `현재 유지 / 부분 수정 / 구조 재설계` 선택지별 영향
8. 사용자 결정 상태

예:

- `without-skill`은 시작 역할 2개를 제시했고 `with-skill`은 1개를 제시했다.
- `with-skill`은 `AGENTS.md` 충돌 파일을 기록했고 `without-skill` 결과에는 해당 관찰이 없다.
- 두 실행의 질문 수는 각각 3개와 1개다.
- 두 실행 환경이 달라 응답 시간은 직접 비교하지 않는다.

이 자료만으로 어느 결과가 더 낫다고 결론 내리지 않는다.

---

## 5. 적용 위치

이 기준은 다음 위치에서 사용한다.

- 시작 진입 역할 출력의 관찰 자료 점검
- 운영 감사 역할과 QA 역할의 사용자 판단 자료 준비
- 회귀 점검에서 원본 결과와 비교 조건 보존 확인
- 타겟 프로젝트에서 `target-evaluation-playbook.md`와 함께 사용자 결정 준비
