# Reentry Rules

이 문서는 하네스 작업이 한 번에 끝나지 않을 때 어느 하네스 Phase로 되돌아가야 하는지와, 다음 시작을 위해 무엇을 남겨야 하는지 정의한다.

재진입은 예외 처리가 아니라 운영 루프의 일부다.

## 핵심 전제

- 운영 감사 역할은 저장소 입력, 역할 경계, 에이전트 정의, 역할 스킬, 오케스트레이션, 로그와 피드백 반영 중 관찰된 축에 따라 후보 하네스 Phase를 설명한다.
- 실제 재진입 Phase와 변경 범위는 사용자가 확정한다.
- 모든 재진입은 `latest-session-summary.md`에 다음 시작 정보로 남아야 한다.
- 재진입은 전체 재생성보다 좁은 Phase 수정부터 본다.

## 기본 재진입 축

- 입력이 약하면 `하네스 Phase 1`
- 역할 경계가 약하면 `하네스 Phase 2`
- 에이전트 정의가 약하면 `하네스 Phase 3`
- 역할 스킬의 `team-spec` 포인터나 트리거가 약하면 `하네스 Phase 4`
- 오케스트레이션과 handoff 기준이 약하면 `하네스 Phase 5`
- 운영 감사에서 구조 불일치가 남으면 `하네스 Phase 6`
- 피드백 반영과 다음 개선 판단이 약하면 `하네스 Phase 7`

## Phase별 재진입 조건

### 하네스 Phase 1로 재진입

- `project-setup.md`가 비어 있거나 방향을 좁히지 못한다
- `domain-analysis.md`가 저장소 근거보다 일반론에 가깝다
- 핵심 사용자 문제나 첫 성공 시나리오가 분명하지 않다

### 하네스 Phase 2로 재진입

- 역할 이름이 범용적이거나 현재 저장소 용어를 반영하지 못한다
- 다음 역할 흐름이 약하다
- 시작 진입 역할과 중심 조율 역할이 섞여 있다

### 하네스 Phase 3으로 재진입

- `team-spec.md`와 `.codex/agents/*.toml`이 일치하지 않는다
- description만으로 트리거 조건을 파악하기 어렵다
- 시작 진입 역할과 중심 조율 역할의 agent 정의가 섞여 있다

### 하네스 Phase 4로 재진입

- `.agents/skills/*/SKILL.md`가 해당 `role_id`의 team-spec 섹션을 명확히 참조하지 못한다
- 역할 스킬이 `team-spec`의 공통 출력 블록을 따르도록 지시하지 않는다
- 역할별 우선 입력, 절차, 다음 역할, 종료 기준이 역할 스킬 본문에 중복되어 drift 위험을 만든다

### 하네스 Phase 5로 재진입

- `orchestration-plan.md`, `team-playbook.md`, `team-structure.md`가 다음 역할 흐름을 분명히 보여주지 못한다
- 시작 진입 역할이 다음 역할, 보류 흐름, 실패 흐름을 안정적으로 안내하지 못한다
- 최신 세션 요약에 다음 시작 정보가 부족하다

### 하네스 Phase 6으로 재진입

- 운영 감사가 누락/불일치/골격 잔존을 남긴다
- 역할 구조가 확장 가능한 팀으로 읽히지 않는다
- 에이전트 정의, 역할 스킬, 보조 운영 문서, 로그가 같은 운영 기준을 말하지 않는다
- 구조·계약 검증 결과, 선택지별 영향, 후보 하네스 Phase와 사용자 결정 상태가 불분명하다

### 하네스 Phase 7로 재진입

- 하네스 Phase 6의 구조 감사는 끝났지만 피드백 반영 위치가 분명하지 않다
- `with-skill`과 `without-skill` 비교 관찰이 약하다
- 사용자가 확정한 변경 범위가 로그와 운영 감사 관찰에 연결되지 않는다

## latest-session-summary.md에 남겨야 할 재진입 정보

최신 요약에는 최소한 아래 항목을 남긴다.

- 다음 시작 역할
- 다음 하네스 재진입 Phase
- 다음 시작 전 우선 확인 입력 파일
- 최근 출력 파일
- 최근 변경 파일
- 남은 위험 또는 미해결 항목
- 사용자 결정 상태와 확정 범위

## 후보 제시와 확정 원칙

- 운영 감사 역할은 전체를 다시 만드는 선택지만 제시하지 않고 가장 이른 계약 실패 지점에 대응하는 부분 수정 후보도 함께 설명한다.
- 구조 재설계 후보는 역할 구조·기준 원천·운영 흐름 전체의 충돌 근거와 `하네스 Phase 0`부터 다시 시작할 영향을 포함한다.
- 어느 후보도 최선으로 판정하지 않으며, 재진입 이유와 영향은 사용자가 비교할 수 있도록 한 문장 이상으로 명확히 설명한다.
- 사용자 결정 전에는 후보로만 기록하고, 결정 후에는 확정된 하네스 Phase와 범위를 별도로 기록한다.
