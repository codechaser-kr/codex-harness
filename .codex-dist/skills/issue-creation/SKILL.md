# Issue Creation

이 스킬은 사용자의 비정형 요청이나 Workflow Engine의 이슈 생성 작업을 GitHub 이슈 초안으로 정리한다. 초안 작성과 검증이 책임이며, 사용자 결정과 실제 GitHub 이슈 생성은 Workflow Engine의 후속 작업에서 처리한다.

## 먼저 읽을 문서

- `../github-workflow-engine/references/github-templates.md`
- `../github-workflow-engine/references/workflow-engine-rules.md`

대상 저장소에 `.github/ISSUE_TEMPLATE/*.md`가 있으면 해당 파일을 실제 본문 형식의 단일 원천으로 먼저 읽는다. `github-templates.md`는 본문 복제본이 아니라 title prefix, label, 필수 섹션, 연결 규칙을 검증하는 계약 문서로 사용한다.

## 책임

1. 요청을 `기능제안`, `정책검토`, `기능변경`, `기능결함` 중 하나로 분류한다.
2. 대상 저장소의 실제 `.github` 이슈 템플릿 형식에 맞춰 본문 초안을 작성한다.
3. 제목 prefix, 라벨, 필수 섹션, 완료 기준, 연관 이슈를 `github-templates.md` 계약으로 검증한다.
4. 원본 이슈가 있으면 새 이슈의 `연관 이슈`에 원본 번호를 기록한다.
5. 정책검토 이슈는 출처에 따라 조건부 후속 작업을 다르게 작성한다.
6. Workflow Engine이 검토할 수 있게 생성 전 위험과 보류 질문을 정리한다.
7. 실제 GitHub 이슈 생성은 Workflow Engine이 수행한다.

## 분류 기준

- 아직 진행 여부를 판단해야 하는 요청은 `기능제안`이다.
- 설계, 정책, 운영 기준 결정이 필요한 요청은 `정책검토`다.
- 구현 범위와 완료 기준이 확정된 기능 추가 또는 수정은 `기능변경`이다.
- 결함, 회귀, 문서와 구현 불일치, 반영 누락은 `기능결함`이다.

## 초안 검증

- 이슈 본문에는 사용자가 확인할 작업 내용, 판단 근거, 완료 기준만 둔다.
- 실제 본문 heading, optional 표기, 기본 체크리스트 형식은 대상 저장소의 `.github/ISSUE_TEMPLATE/*.md`를 따른다.
- 대상 저장소의 `.github` 템플릿이 없거나 `github-templates.md` 계약과 불일치하면 차이, 영향 범위, 보류 질문을 출력한다.
- 완료 기준은 이슈를 종료해도 되는지 판단할 수 있는 체크리스트로 쓴다.
- 연관 이슈가 없으면 `N/A`로 둔다.
- 기능결함 이슈 생성 시 `원인과 해결 방향은 무엇인가요?`는 비워 둔다.
- 기능제안의 `판단 결과`는 생성 시 미체크 상태로 둔다.
- 정책검토의 `검토 결과`는 생성 시 비워 둔다.

## 정책검토 후속 작업 규칙

- 독립 정책검토 또는 기능제안에서 이어진 정책검토의 `검토 결과`에 실행 산출물 변경 필요가 기록될 수 있으면 `필요한 경우 기능 변경 이슈의 작업 범위와 완료 기준에 반영` 항목을 추가한다.
- 기능결함에서 이어진 정책검토의 후속 연결은 정책검토 흐름의 `기능결함 이슈 반영` 작업에서 원본 기능결함 이슈에 반영한다.
- 체크항목의 근거가 되는 이슈나 PR이 있으면 항목 뒤에 `(#번호)`를 붙일 수 있다.

## 출력 형식

초안을 제시할 때는 다음을 함께 보여준다.

- 이슈 유형
- 제목
- 라벨
- 본문 초안
- 연관 이슈
- 생성 전 확인해야 할 위험 또는 보류 질문
