# Policy Plan

`정책검토` 이슈에서 변경하거나 적용할 정책을 구체적으로 설계하기 위한 계획을 작성한다.

## 먼저 읽을 문서

- `../github-workflow-engine/references/workflow-engine-rules.md`에서 `Policy Plan 출력 판정 규칙` 섹션만 읽는다.
- `../github-workflow-engine/references/github-templates.md`

## 입력

- 정책검토 이슈 번호와 본문
- `무엇을 결정해야 하나요?`, `왜 지금 필요한가요?`, `선택지는 무엇인가요?`
- 연관 기능제안 또는 기능변경 이슈
- 관련 설계 문서와 현재 정책 또는 설계 원천
- 현재 코드, 템플릿, 스킬, 설정 상태
- 이미 merge된 연결 PR

## 책임

1. 정책검토 이슈의 결정 질문과 배경을 확인한다.
2. 현행 설계 문서, 코드, 템플릿, 스킬, 설정에서 정책 설계에 필요한 근거를 수집한다.
3. 변경하거나 적용할 정책의 설계 후보를 번호 목록으로 정리한다.
4. 각 후보의 정책 설계 내용, 판단 근거와 위험, 설계 문서 반영 대상을 함께 제시한다.
5. 가장 적합한 추천 설계가 있으면 근거와 함께 제시하되, 최종 판단은 사용자 결정으로 남긴다.
6. 정책검토 흐름의 설계 문서 반영은 필수로 보고, 각 후보마다 설계 문서 반영 대상과 반영 단위를 제안한다.
7. 설계 문서 반영 이후 기능변경 전환으로 이어질 구현 범위를 제안한다.
8. Workflow Engine이 확인할 보류 질문을 반환한다.

각 정책 설계 후보에는 필수 설계 문서 반영 대상과 반영 단위를 포함한다. 정책으로 확정할 설계 내용이 없으면 진행 보류 질문으로 반환한다.

## 필수 출력 섹션

정책 설계 계획은 다음 한글 섹션과 항목을 순서대로 빠짐없이 채운다. 필수 내용을 채울 수 없으면 정책 설계를 확정하지 말고 `보류 질문`에 확인할 내용을 기록한다.

- `기준 이슈`
- `결정 맥락`: 결정 질문, 현재 상태, 참조한 설계 문서와 연관 이슈
- `정책 설계 후보`
  - `후보 ID`
  - `정책 설계`: 적용 범위와 상세 설계를 포함한다.
  - `판단 근거와 위험`
  - `설계 문서 반영 대상`
  - `설계 문서 반영 단위`
  - `검증 기준`
  - `설계 반영 후 기능변경 전환 범위`
- `추천 설계`
- `보류 질문`: Workflow Engine이 확인할 보류 질문
