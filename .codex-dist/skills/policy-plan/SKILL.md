# Policy Plan

`정책검토` 이슈에서 변경하거나 적용할 정책을 구체적으로 설계하기 위한 계획을 작성한다.

## 먼저 읽을 문서

- `../github-agentic-loop/references/artifact-output-contract.md`에서 ``정책 계획(`policy-plan`) 출력 판정 규칙`` 섹션만 읽는다.
- `../github-agentic-loop/references/artifact-handoff-contract.md`
- `../github-agentic-loop/artifact-manifests/policy-plan.json`
- `../github-agentic-loop/references/github-templates.md`

## 입력

- 정책검토 이슈 번호와 본문
- `무엇을 결정해야 하나요?`, `왜 지금 필요한가요?`, `선택지는 무엇인가요?`
- 연관 기능제안 또는 기능변경 이슈
- 관련 설계 문서와 현재 정책 또는 설계 원천
- 현재 코드, 템플릿, 스킬, 설정 상태
- 이미 merge된 연결 PR

## 책임

1. 정책검토 이슈의 결정 질문과 배경을 확인한다.
2. 현행 설계 문서, 코드, 템플릿, 스킬, 설정에서 정책 설계에 필요한 근거를 수집한다.
3. 변경하거나 적용할 정책의 설계 후보를 번호 목록으로 정리한다.
4. 각 후보의 정책 설계 내용, 판단 근거와 위험, 설계 문서 반영 대상을 함께 제시한다.
5. 가장 적합한 추천 설계가 있으면 근거와 함께 제시하되, 최종 판단은 사용자 결정으로 남긴다.
6. 정책검토 흐름의 설계 문서 반영은 필수로 보고, 각 후보마다 설계 문서 반영 대상과 반영 단위를 제안한다.
7. 설계 문서 반영 이후 기능변경 전환으로 이어질 구현 범위를 제안한다.
8. Workflow Engine이 확인할 보류 질문을 반환한다.

각 정책 설계 후보에는 필수 설계 문서 반영 대상과 반영 단위를 포함한다. 정책으로 확정할 설계 내용이 없으면 진행 보류 질문으로 반환한다.

## 출력

- 공통 handoff 계약의 닫힌 envelope만 반환한다.
- `artifact_type: policy-plan`을 사용하고 `artifact`는 `policy-plan.json` manifest에 맞춰 구성한다.
- 설계는 사용자 검토용 후보이며 정책검토 이슈의 `검토 결과`나 설계 문서에 반영할 확정값이 아니다. Markdown 표시는 runtime renderer가 담당한다.

## 하지 않는 일

- 정책을 확정하거나 사용자 선택을 해석하지 않는다.
- 정책검토 이슈, 설계 문서, 기능변경 이슈를 변경하거나 GitHub 상태를 변경하지 않는다.
- 확인된 정책검토 이슈와 설계 원천의 범위를 넘어 구현 단위나 후속 흐름을 추가하지 않는다.

## 사용자 결정

- 추천 설계는 결정 후보일 뿐이다. 정책 확정, 설계 문서 반영 요청, 기능변경 전환의 사용자 결정과 실행 요청 확정은 `github-agentic-loop`가 맡는다.

## 중단 조건

- 결정 질문, 선택지, 설계 원천, 연관 범위가 없거나 충돌하면 정책 설계를 확정하지 않는다.
- 입력이 정책검토 범위를 벗어나거나 필수 설계 문서 반영 대상을 식별할 수 없으면 구체적인 사유와 재개에 필요한 입력을 `보류 질문`에 반환한다.

## 후속 전이

- 제어와 기존 출력 구조를 `github-agentic-loop`에 반환한다.
- Workflow Engine이 산출물 판정과 사용자 결정을 거쳐 정책 확정, 설계 반영, 기능변경 전환의 다음 작업을 확정한다.

## Structured artifact handoff

의미 내용은 위 정책·설계 문서 판단에 따라 작성하고, 기계 구조는 `policy-plan.json`만 따른다. envelope 밖의 설명이나 직접 조립한 Markdown을 반환하지 않는다.
