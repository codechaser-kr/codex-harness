# 하네스 생성기 평가 코퍼스

이 디렉터리는 전역 `harness` 생성기를 바꾼 뒤, 실제 타겟 프로젝트에서 나온 결과를 다시 읽고 개선 방향을 남기는 평가 코퍼스다.

목적은 타겟 프로젝트를 자동으로 고치는 것이 아니다. 생성된 하네스가 어떤 점에서 약했는지, 그 약점이 타겟 로컬 보강으로 충분한지, 생성기 reference까지 고쳐야 하는지를 기록하는 데 있다.

## 기록 원칙

- 타겟 프로젝트 파일은 이 디렉터리에서 직접 수정하지 않는다.
- 평가는 Markdown 문서로 남기고, 별도 실행기나 외부 서비스에 의존하지 않는다.
- 단일 타겟 프로젝트에서 나온 관찰은 먼저 타겟 로컬 보강 후보로 분류한다.
- 여러 타겟 프로젝트에서 같은 결함이 반복될 때만 생성기 환류 후보로 승격한다.
- 같은 타겟을 다시 검토했다면 재검토 메모를 남기고, 이전 판정과 달라진 결함을 구분한다.
- 평가 결과는 `evolution-contract.md`, `target-evaluation-playbook.md`, `quality-evaluation-guide.md` 기준에 맞춰 작성한다.

## 권장 구조

```text
docs/evaluations/
├── README.md
└── targets/
    └── <target-repo-name>/
        └── <YYYY-MM-DD>-<short-topic>.md
```

## 평가 문서 필수 항목

- 타겟 프로젝트와 브랜치
- 평가한 생성 결과
- 현재 판정
- 가장 약한 축
- 타겟 로컬 보강 후보
- 생성기 환류 후보
- 다음 재진입 Phase
- 재검토 메모
- 검증 메모
